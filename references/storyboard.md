# Storyboard — 内容分镜而非固定页数

## 每页必填六项

1. `id`：顺序号，01、02 等。
2. `job`：这页对读者的唯一作用（抓住注意/解释概念/教会一步/比较/验证/总结等）。
3. `headline`：精确最终标题，非“这里写一个标题”。
4. `body`：文字预算和必须保留的文案。
5. `visual`：图像类型+明确构图，需真实截图则列出素材ID。
6. `risk`：哪些字段不能错、哪些依据需审核。

可按需增加 `source`, `references`, `author_note`, `design_variation`。

## 角色可任意组合

| 页面角色 | 读者要解决的问题 | 常用布局（可替换） |
|---|---|---|
| hook | 为什么继续看 | 文字主导、照片主导、对比主导 |
| context | 这件事为什么与我有关 | 场景照片、叙事拼贴 |
| principle | 原理和关系是什么 | 单向数据流、层级树、对照示意 |
| how_to | 我怎么做 | 截图为主，局部放大，编号线索 |
| checklist | 我需要记住什么 | 分类清单、网格、勾选结构 |
| comparison | 哪种方案适合我 | 真正可比较的轴/表格/卡片 |
| evidence | 我凭什么相信 | 带来源的数据、真实结果、可复现步骤 |
| takeaways | 我得到了什么 | 一个总结主句、两三个要点 |
| story | 接下来发生什么 | 连续视觉叙事 |
| next_step | 下一步是什么 | 明确行动或进一步阅读路线 |

不要求所有角色都出现，也不强制以 hook 开头。用户只要一张就做一张。

## 让系列有“统一但不重复”的秩序

保持统一：颜色关系、文字层级、线条/图片处理、边距节奏、标题语气；改变单页：画面比例、视觉主角、文字数量、分栏方式、图片尺寸。

给每页设计 `hero_type`：`type` / `diagram` / `screenshot` / `photo` / `illustration` / `data`，尽量避免全篇只用一种；如果用户要求一种统一模版则遵从。

## 文字预算只是建议，不是硬性字符门槛

- 封面：标题最突出，副标题可有可无。
- 原理页：节点标签尽量短，补充说明只留关键句。
- 操作页：真正应看的软件或操作图占视觉大部分。
- 精确提示词、代码：优先局部展示与复制配套文本，不为塞入图片而缩到看不清。

## 输出给作者确认的结构

用一张可讨论的表或编号段落，列出全部页的标题、视觉思路与素材缺口；明确“预计多少张”以及哪些只能画示意，哪些必须有真实图片。需要确认时先展示可修改的分镜再制作。
