# Image Production — 单页生图、正确引用、渐进修订

## 每页一张，不是每次一套拼版

生图调用只包含**本页**的文案、页面角色、参考素材、构图和分辨率/比例要求。不要把“生成第4、5、6、7页”写成一个让模型画四页拼图的提示。工具可以连续调用多次，但每张最终结果必须是能独立发布的一张图片。

**生图工具优先**：用户要图就使用实际的图片生成/编辑工具；不可使用时清楚说明缺失，并生成供用户执行的提示词与计划，不得假称已生图。

## 单页 prompt 基本顺序

1. 页面角色与唯一视觉主体。
2. 精确内容（标题、副标题、必要的节点/数据、署名*若用户提供*）。
3. 画布比例或分辨率、页边距和安全区域。
4. 当前风格包 invariants 和页级 variant。
5. 布局要求：标题区、主视觉区、辅助信息区、阅读顺序。
6. 参考图/真实素材指引及“不改写真实UI”的明确限制。
7. 本页禁用内容；不得生成多页拼版，不能臆造数字/文字。
8. 交付标准：独立 PNG/其他指定格式，真实文件尺寸核验。

一张页面重做时，必须保留“标题内容和已批准事实”；只针对失败点调整生成指令。

## 默认直接生成完整图页

- 每页的背景、插画、排版和授权的页内文字都交给图像生成/编辑模型，直接生成完整成品；不要先做一张装饰底图，再默认用代码、SVG/HTML/CSS 或模板把文字叠上去。
- 把必须显示的文字原样放进该页 prompt。图中文字错误或不清楚时，先精简文字、明确层级，再用图像编辑模型局部修改或重新生成；每次修改后逐字核对。
- 为了可读性，优先把长原文压缩成读者完成任务所必需的步骤、标签或结论。不能准确塞入的长命令、公式、代码或表格，不得缩到手机上看不清，也不得擅自改成代码排版；先找真实来源图/截图，或向用户说明缺口。
- 只有用户明确要求可编辑排版，或具体内容必须保持精确且图像模型无法保真时，才提出受控排版例外；说明为什么需要、哪些元素会用它，并得到用户同意后再做。例外限于确实需要精确的部分，不把整张图变成“生底图后代码补字”。
- 提供长 prompt 供读者复制时，图片内只展示清楚可读的摘要；是否需要独立的可复制文本由用户决定。
- 所有页内文字最终都要在手机画面大小下可读、可辨。

## 真实截图与图片编辑

- 将用户提供或已核实的真实截图作为优先素材，不使用模型从零“复现”界面来冒充真实截图。
- 允许裁切、放大、遮盖隐私、添加明确注释；保留菜单项、按钮、UI状态原貌。
- 先让图像编辑模型在保留截图原貌的前提下完成整页设计。若它改坏真实 UI，回到原截图并明确说明模型无法保真；只有用户同意精确素材合成例外后，才用原图作为真实图层。不得用伪造界面补缺。
- 实物、真人照片同理：不要在没有依据的情况下增加来源图没有的事实或证据。

## 视觉样张与 A/B

复杂风格可以先生成封面和最难内页；用户明确要求直接批量生成时，跳过多次审批但仍按页制作与核对。A/B 只在有实际视觉差异时才有意义，不能仅换背景色。

## 统一与变化

若工具支持参考图，把已批准封面作为**风格参考**，不是“复制同一版面”。页级换布局。所有页面的主要内容应由同一视觉体系联系，同时避免每页都像同一种PPT卡片。

## 文件核验

模型未必输出宣称的精确分辨率。导出后检查实际图片尺寸，必要时做不会截断文字的受控调整。正式交付按 `references/qa-protocol.md` 运行 `scripts/qa_images.py --strict` 和 `scripts/verify_final_qa.py`，确认文件可完整解码、确切页数、命名、宽高和哈希。脚本不会检查错字或图像真实性。图像受限时不可只做一张含多页的预览冒充独立交付。
