# Visual DNA: transferable style, not a page stencil

Create a Visual DNA record from one or more user-provided images, a style pack, or researched references. Record references and confidence. Distinguish **observed** features from inferred preferences.

## Extract

- Format and background treatment (fixed/variable, bright/dark, texture)
- Palette and usage roles, not merely color swatches
- Title scale, font category, weight, linebreak rhythm and contrast
- Secondary text, captions, code, badges, numerals and metadata treatments
- Alignment, margins, spacing ratios, whitespace and grid behaviors
- Image handling: photography, crop, authentic screenshot fidelity, illustration, diagrams
- Reusable identity components: header, section marker, footer, author mark if present
- Accent syntax: lines, dividers, numerals, arrows, fills; how not to overuse them
- Variation budget: elements that can change by page, repetition to avoid, forbidden motifs
- Provenance and usage rights for each example visual

Use `templates/visual-dna.md` for output. A style pack should describe generalized traits, not contain another creator's copied content or logo unless user has rights. Do not claim training or learning weights.

## Precedence

Explicit user instructions > requested exact reference features > approved project Visual DNA > selected style pack > agent defaults.

**Template identity != body layout.** Even if source samples feature two-column screenshots repeatedly, this does not mean future pages must use two columns. Use the content task, source geometry, density, and page sequence to design new layouts under the same DNA.

When user likes specific pages, lock only the confirmed attributes; user may approve a color system without approving every layout. On large revisions, document which approved traits remain.
