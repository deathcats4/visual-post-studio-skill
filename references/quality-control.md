# Quality Control — 真实完成而不是“好像做完了”

## 验收清单

**内容**
- [ ] 每页只有一个主要读者任务，标题与配图同义。
- [ ] 核心事实与提供来源一致；无编造数据、研究结论、软件结果。
- [ ] 术语/数字/人名/路径/文件名/引号/单位正确。
- [ ] 读者不会因为关键步骤遗漏而操作失败。

**视觉**
- [ ] 首页缩小为列表缩略图仍能读懂主题。
- [ ] 内页正文在手机屏幕上可辨，不用眯眼。
- [ ] 每页构图和视觉重心适合内容，避免全篇机械重复。
- [ ] 风格一致（字、色彩逻辑、留白、素材处理），无不必要的炫技元素。
- [ ] AI文字无错字/乱码/重叠/溢出/切断。
- [ ] 真实截图未被改写、错标、篡改；隐私信息已遮挡。

**交付**
- [ ] 实际图片数量正确；每张图是完整独立的单页文件，不是拼版。
- [ ] 图片真实尺寸、画幅与要求一致，或已明确告知偏差。
- [ ] 文件名按顺序编号、可单独打开。
- [ ] 图文配文、标签与图中事实一致；没有虚假承诺。
- [ ] 参考图来源及重用权明确，未将私人素材混入公共包。

## 发现问题如何返工

写一条精确 defect record：`page / location / observed issue / intended correction / constraints (must preserve)`。只返工涉及的页面。用户提供区域坐标时按坐标执行，不把其余页面重画。

图像模态检错：大字号、小字号、UI文字、数字、文件扩展名都要逐项检查。不能因为“美观”就放过技术性错字。

## 自动测试边界

最终文件验收遵循 `references/qa-protocol.md`：`qa_images.py --strict` 检查 PNG/JPEG 完整解码、确切页数、编号、尺寸、重复和哈希，`verify_final_qa.py` 对当前文件复核。旧版 `validate_project.py` 只读取 PNG 文件头，不能证明文件完整，保留作兼容命令。

上述脚本**不能判断审美、事实、文本错误或是否真实引用用户截图**。这些需要实际视觉检查与内容审核。
